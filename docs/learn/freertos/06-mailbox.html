6. Mailbox: the latest value main/app_ipc.c:58

Commands must all arrive; sensor state only needs to be fresh. Same queue, used differently.

Build it from first principles

Two kinds of data

An event or command counts every time: skipping "stop" is a bug. A state only matters in its latest version: a reader that wants the robot's position does not want the position of 30 ms ago.

What a queue does to state

Put 100 snapshots per second in a normal queue and the reader gets the oldest first, so it lags; if it reads slower than 100 Hz, the queue fills and the sensor blocks or drops new data.

The mailbox

Make the queue one slot long. The writer replaces the slot with xQueueOverwrite (never blocks); readers copy it with xQueuePeek, which does not remove it, so any number of tasks can read the same value.

QueueHandle_t snap_q = xQueueCreate(1, sizeof(sensor_snapshot_t));

xQueueOverwrite(snap_q, &snap);   // sensor task: replace
xQueuePeek(snap_q, &copy, 0);     // any reader: copy, keep

Why these values

Why length 1, exactly? xQueueOverwrite is only defined for a queue of length 1: "overwrite" means "replace the one item". With more slots there would be no single latest value to replace.
How much does a read cost? sizeof(sensor_snapshot_t) = 32 bytes (3 ToF distances, yaw, yaw rate, 2 encoder counts, a timestamp). Copying 32 bytes under the queue's internal lock takes well under a microsecond.
And the status mailbox? sizeof(motion_status_t) = 40 bytes: state, progress, target and the 28-byte report of the last move. The app peeks it whenever it needs progress or a result.
To remember. State goes in a mailbox (latest value wins); commands and events go in a queue (every value counts). Mailbox = length-1 queue + xQueueOverwrite + xQueuePeek.

Deep dive: what a mailbox cannot tell you

A peek returns the newest value but not whether it is new since your last read: two peeks 1 ms apart return the same snapshot. That is why the motion task does not poll the mailbox. It waits for a "new sample" signal (page 7), so every control step uses fresh data exactly once.
